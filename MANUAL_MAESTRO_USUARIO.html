1. Visión General y Propósito del Sistema

OSS Atlas es una plataforma de inteligencia de software B2B diseñada para eliminar la fricción técnica y el alto costo operativo en la adopción corporativa de tecnologías de código abierto. En consultoría e ingeniería tradicional, un equipo de arquitectos invierte habitualmente entre 15 y 20 horas por proyecto realizando tareas repetitivas:

  • Investigar repositorios en GitHub y filtrar proyectos abandonados o sin mantenimiento.
  • Verificar compatibilidad de licencias permisivas (MIT, Apache 2.0, BSD) frente a restrictivas (AGPL, GPLv3) para evitar riesgos legales.
  • Diseñar y validar manifiestos de contenedores compatibles entre las capas de Autenticación, Base de Datos, Pagos e Inteligencia Artificial.

OSS Atlas resuelve este problema mediante un Catálogo Cardinal Ponderado, un Asistente Conversacional RAG con Cero Alucinación y un Generador de Guías de Integración descargables (.md y .pdf) adaptadas específicamente para Windows y macOS.

3. Módulos de la Plataforma & Manual de Operación

3.1. Explorador de Categorías y Catálogo Normalizado

El catálogo categoriza las herramientas líderes de código abierto en 4 dominios empresariales:

  • AUTH (Autenticación e IAM): Keycloak, Authentik, Zitadel, Ory Kratos, Casbin, OpenFGA.
  • DBS (Bases de Datos & Vectores): Supabase (PostgreSQL + pgvector), Qdrant Vector Engine, PostgreSQL Relacional Core.
  • PAYMENTS (Pagos y Facturación Recurrente B2B): Juspay Hyperswitch, Kill Bill, Lago.
  • AI (Modelos de Lenguaje & RAG Auto-Hospedado): Meilisearch, vLLM Inference Engine, LlamaIndex, LangChain.

Métrica Exclusiva: Health Score Cardinal

Cada componente se clasifica mediante una fórmula matemática estricta y transparente:

Health Score = (Velocidad de Commits × 0.15) + (Seguridad y Auditoría Estructural × 0.20) + (Documentación y Madurez de Comunidad × 0.65)

3.2. Motor de Búsqueda Híbrida RRF (Reciprocal Rank Fusion)

Para evitar fallos ante términos técnicos o números de serie, el motor combina dos canales independientes:

Score_RRF(doc) = 1 / (60 + Rango_Lexico(doc)) + 1 / (60 + Rango_Vectorial(doc))

El índice de texto completo utiliza el diccionario simple de PostgreSQL en lugar del algoritmo Snowball, asegurando que tokens como SKU-9941A, HNSW, RS256 o nombres exactos de funciones no sean descompuestos erróneamente.

3.3. Asistente Conversacional RAG B2B (Cero Alucinación)

El motor RAG sintetiza arquitecturas auto-hospedadas combinando únicamente piezas validadas en el catálogo:

  • Faithfulness (Fidelidad de Contexto): 1.00 — Cero dependencias inventadas.
  • Context Precision & Recall: ≥ 0.96.
  • Umbral de Seguridad: Si la similitud del coseno es inferior a 0.78, el sistema declina la generación y solicita mayor contexto para evitar arquitecturas inseguras.

3.4. Generador de Guías de Integración (.md & .pdf) para Windows y macOS

Desde cualquier tarjeta del catálogo o resultado del asistente RAG, los ingenieros pueden hacer clic en Ver Guía de Integración / View Integration Guide:

  • Pestañas Interactivas: Permiten alternar entre ver ambos sistemas en paralelo, solo Windows (PowerShell, WSL2) o solo macOS (Terminal, Homebrew, Colima).
  • Botón Copiar: Copiado en 1 clic de scripts con notificación visual.
  • Descarga en Markdown (.md): Documento técnico estructurado para documentación de proyectos o repositorios Git.
  • Descarga en PDF (.pdf): Generado con la librería jspdf directamente en el navegador del usuario, con formato corporativo de alta calidad, insignias, tablas y recomendaciones de seguridad.

4. Guía de Integración Técnica en Sistemas Operativos

4.1. Despliegue en Windows (PowerShell / WSL2)

Procedimiento estandarizado para entornos de desarrollo y staging en Windows 10/11:

# 1. Validar el estado del subsistema WSL2
wsl --status

# 2. Crear directorio de persistencia de datos local
New-Item -ItemType Directory -Force -Path "$HOME\oss-atlas-data\postgres"

# 3. Lanzar contenedor con reinicio automático y volumen montado
docker run -d --name postgres-core `
  -p 5432:5432 `
  -e POSTGRES_PASSWORD=postgres `
  -v "$HOME\oss-atlas-data\postgres:/var/lib/postgresql/data" `
  --restart unless-stopped `
  postgres:16-alpine

# 4. Verificar salud del servicio
docker ps --filter "name=postgres-core"
docker logs --tail 25 postgres-core

4.2. Despliegue en macOS (Terminal / Homebrew / Colima)

Procedimiento nativo optimizado para arquitecturas Apple Silicon (M1/M2/M3/M4) e Intel x86_64:

# 1. Instalar y aprovisionar Colima con recursos dedicados
brew install colima docker docker-compose
colima start --cpu 4 --memory 4 --disk 40

# 2. Crear directorio de almacenamiento persistente
mkdir -p "$HOME/oss-atlas-data/postgres"

# 3. Ejecutar contenedor con soporte de arquitectura
docker run -d --name postgres-core \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=postgres \
  -v "$HOME/oss-atlas-data/postgres:/var/lib/postgresql/data" \
  --restart unless-stopped \
  postgres:16-alpine

# 4. Validar conectividad de red local
docker ps --filter "name=postgres-core"
curl -I -s http://localhost:5432 || true

5. Guía de Solución de Problemas (Troubleshooting)

Entorno Síntoma / Mensaje de Error Diagnóstico & Causa Raíz Solución Técnica Paso a Paso
Windows bind: address already in use Rango de puertos reservados por Hyper-V en Windows. Consultar puertos excluidos: netsh interface ipv4 show excludedportrange protocol=tcp y reasignar a otro puerto en docker run -p.
Windows Conexión bloqueada desde otros equipos Firewall de Windows Defender con política de bloqueo entrante. Crear regla en PowerShell Administrador: New-NetFirewallRule -DisplayName "OSS-Atlas" -Direction Inbound -LocalPort 5432 -Protocol TCP -Action Allow.
macOS I/O lento en volúmenes compartidos Driver 9p o sshfs por defecto en máquinas virtuales. Reiniciar Colima con el motor nativo de Apple: colima start --vm-type=vz --vz-rosetta.
macOS exec /bin/sh: exec format error Imagen Docker compilada para x86 ejecutada en Apple Silicon sin emulador. Agregar la bandera explícita: --platform linux/amd64 en el comando de ejecución.
General 429 Rate Limit Exceeded (GitHub) Consumo de cuota horaria por consultas repetidas. La aplicación activa de forma transparente la caché ETag condicional (HTTP 304) consumiendo 0 cuota.

6. Plan de Pruebas y Aseguramiento de Calidad (QA Checklist)

Para la sesión de pruebas de mañana, se seguirán los siguientes casos de prueba estandarizados:

✓
Prueba 1: Límite de Consultas Gratuitas (Paywall Trigger)
Ejecutar 3 consultas en el Asistente RAG con el plan Community activo. Verificar que la 4.ª consulta bloquee la inferencia y despliegue el modal promocional del plan Pro Architecture.
✓
Prueba 2: Simulación de Pasarela de Pagos (PayPal, Wenia USDW, Transferencia)
Completar el checkout seleccionando PayPal y Wenia; verificar que se registre el token oss_atlas_sub en localStorage y que el asistente quede desbloqueado permanentemente.
✓
Prueba 3: Búsqueda Híbrida RRF con Tokens Alfanuméricos
Ingresar términos como SKU-9941A, HNSW, RS256 y validar que el FTS con diccionario simple sitúe la herramienta correcta en el rango #1 sin distorsión de stemming.
✓
Prueba 4: Descarga e Inspección de Archivos .md y .pdf
Generar las guías de PostgreSQL, Keycloak y Qdrant; abrir los archivos PDF en un lector externo y corroborar la legibilidad tipográfica, cajas de código y paginación.
✓
Prueba 5: Sincronización Continua con Validación ETag
Ejecutar el endpoint de sincronización /api/v1/catalog/sync y validar que responda HTTP 304 Not Modified cuando no hay cambios en los repositorios de GitHub.
✓
Prueba 6: Conmutación de Idioma (Bilingual Stress Test)
Alternar entre 🇪🇸 ES y 🇺🇸 EN tanto en escritorio como en móvil; verificar que todos los textos, descripciones, badges y modales se mantengan sincronizados.
